Once the package is [installed and configured](/laravel-steam-api-sdk/configuration),
the `Steam` facade is the only entry point. Three things carry the rest: the
**`SteamId`** value object every endpoint takes, the **resources** that send them, and the
readonly **DTOs** they return.

## The `SteamId` value object

`SteamId` — from the underlying SDK — is the only identifier the facade accepts;
no raw strings. Build one from a verified 64-bit ID, or parse untrusted input:

<Tabs syncKey="steam-id-source">
  <TabItem label="Verified ID">
    ```php
    use Fkrzski\SteamApiSdk\ValueObjects\SteamId;

    // Throws InvalidSteamIdException on anything but a 17-digit numeric ID.
    $id = SteamId::fromSteamId64('76561198000000000');
    ```
  </TabItem>
  <TabItem label="User input">
    ```php
    use Fkrzski\SteamApiSdk\ValueObjects\SteamId;

    // Returns null for anything that is not a SteamID64 or /profiles/<id> URL.
    $id = SteamId::tryFromInput('https://steamcommunity.com/profiles/76561198000000000');
    ```
  </TabItem>
</Tabs>

Read the value with `$id->value` (or `(string) $id`) and compare two IDs with
`$id->equals($other)`. It is the same object the
[`AsSteamId`](/laravel-steam-api-sdk/eloquent-cast) cast stores on your models.

<Aside type="tip">
[`SteamIdRule`](/laravel-steam-api-sdk/validation) does the same parsing inside a
validation cycle, without a Steam Web API call.
</Aside>

## Calling the facade

Each endpoint sits on the [resource](/laravel-steam-api-sdk/api-reference#resources) for its
Steam interface, which builds the request, sends it through the shared connector, and decodes
the response into typed DTOs — objects, never arrays:

```php
use Fkrzski\LaravelSteamApiSdk\Facades\Steam;

$summaries    = Steam::users()->summaries([$id]);
$bans         = Steam::users()->bans([$id]);
$friends      = Steam::users()->friends($id);
$groups       = Steam::users()->groups($id);
$resolvedId   = Steam::users()->resolveVanityUrl('gabelogannewell');
$library      = Steam::players()->ownedGames($id, appIdsFilter: [381210]);
$recentGames  = Steam::players()->recentlyPlayedGames($id);
$level        = Steam::players()->steamLevel($id);
$badges       = Steam::players()->badges($id);
$quests       = Steam::players()->communityBadgeProgress($id);
$stats        = Steam::stats()->userStats($id, appId: 381210);
$achievements = Steam::stats()->achievements($id, appId: 381210);
$playing      = Steam::stats()->currentPlayers(appId: 381210);
$globalStats  = Steam::stats()->globalAchievements(gameId: 381210);
$gameSchema   = Steam::stats()->schema(appId: 381210);
$versionCheck = Steam::apps()->upToDateCheck(appId: 440, version: $installedVersion);
$servers      = Steam::apps()->serversAtAddress('108.181.62.21');
$relayNetwork = Steam::apps()->sdrConfig(appId: 730);
$news         = Steam::news()->appNews(appId: 440);
$newsFeed     = Steam::newsFeed(appId: 440);
$serverTime   = Steam::webApi()->serverTime();
$webApis      = Steam::webApi()->supportedApis();
```

The resources are the base SDK's own, handed back as the connector builds them, while
`newsFeed()`, a lazy collection paging through `appNews()`, is the bridge's. The
[API reference](/laravel-steam-api-sdk/api-reference) lists what each returns; the DTO
properties and enums live in [Data objects](/php-steam-api-sdk/dto-reference).

`supportedApis()` sends the key when one is configured and goes out without it otherwise, so it
lists the methods your key can call on top of the anonymous ones. Steam answers a rejected key
with a `403`, which the base SDK raises as `InvalidApiKeyException`.

<Aside type="caution" title="A hidden profile has no creation date">
Steam withholds `timecreated` along with the rest of the details, so
`PlayerSummary::$timeCreated` is null for a private profile and a friends-only one alike.
`communityVisibility` tells the two apart: Steam reports the second as
`CommunityVisibility::FriendsOnly`.
</Aside>

## Concurrent requests

Use `pool()` to fan out several requests at once instead of sending them serially:

```php
use Fkrzski\LaravelSteamApiSdk\Facades\Steam;
use Fkrzski\SteamApiSdk\Http\Requests\IPlayerService\GetOwnedGamesRequest;
use Fkrzski\SteamApiSdk\Http\Requests\ISteamUser\GetPlayerSummariesRequest;
use Saloon\Http\Response;

Steam::pool(
    requests: [
        new GetOwnedGamesRequest($id, [381210]),
        new GetPlayerSummariesRequest([$id]),
    ],
    concurrency: 2,
    responseHandler: fn (Response $response) => $response->dto(),
)->send()->wait();
```

Pools work with raw Saloon requests, so the handler reads each DTO with `->dto()`, built before
the request settles. A failed request goes to `exceptionHandler` instead: one Steam reports in a
`200`, such as a hidden games list, an answer the SDK cannot read, and one whose DTO it cannot
build alike.

<Aside title="Pooled requests still cost quota">
Every request in a pool draws on the same limits as any other call — see
[Rate limiting](/laravel-steam-api-sdk/rate-limiting).
</Aside>

## Escape hatch

For a custom request the resources don't cover, reach for the connector directly:

```php
use Fkrzski\LaravelSteamApiSdk\Facades\Steam;

$connector = Steam::connector();     // the underlying SteamConnector
$response  = Steam::send($request);  // send any Saloon Request, get the raw Response
```

`send()` raises what the resources raise, inside the call: a `GetOwnedGamesRequest` for a hidden
profile throws there, though Steam answers it with a `200`. `Steam::connector()->debug()` dumps
every request after it with the key masked as `key=***` — see
[Debugging](/php-steam-api-sdk/hooks-and-debugging#debugging). A hook added on the connector dies with it, so
listen to the [events](/laravel-steam-api-sdk/events) instead. `Steam::connector()->sender()` is the
base SDK's `SteamSender` wrapper, so Guzzle middleware goes on a
[sender of your own](/laravel-steam-api-sdk/configuration#sender).

<Aside type="caution">
The connector binding is **scoped** — one instance per request. Do not hold it
past the request that resolved it; on a long-lived worker it would carry its API
key into the next one.
</Aside>

## Exceptions

The connector runs Saloon's `AlwaysThrowOnErrors` and maps every failure onto an
SDK exception, so a non-2xx response never reaches you as a DTO. All of them
extend `SteamApiException`, so one catch handles the lot:

```text frame="none"
SteamApiException                   (root, extends RuntimeException)
├── ApiKeyNotConfiguredException    No key configured for a request that needs one.
├── AppNewsUnavailableException     App whose news Steam does not publish, or an unknown app.
├── AppNotFoundException            App ID Steam does not know.
├── AppVersionUnavailableException  No server version to check, or an unknown app.
├── InvalidApiKeyException          Steam rejected the key, or received none.
├── InvalidServerAddressException   Address is neither IPv4 nor IPv4:queryport.
├── InvalidSteamIdException         Malformed SteamID64.
├── ProfileNotPublicException       Profile, games list, groups or stats private, or missing where Steam can't tell.
├── StatsUnavailableException       No stats for that game, or the profile hides them.
├── SteamConnectionException        Steam never answered: timeout, DNS, TLS, refused, cut-off body.
├── SteamRateLimitException         A local limit ran out, or Steam answered 429; exposes the Limit.
├── SteamUserNotFoundException      No Steam user has the vanity name.
├── TooManySteamIdsException        More than 100 IDs in a request built by hand.
├── UnreadableResponseException     An answer that is not JSON, or lacks its envelope.
├── FakeNotInstalledException       Facade assertion without Steam::fake(). (Laravel bridge)
├── FakeOutsideTestsException       Steam::fake() outside tests. (Laravel bridge)
└── InvalidSteamConfigException     A steam-api value the bridge cannot use. (Laravel bridge)
```

Catch the leaf you care about, or the root. The
[API reference](/laravel-steam-api-sdk/api-reference) notes which endpoint raises which.

A message built from a Steam response opens with the Steam method:
`GetNumberOfCurrentPlayers: No Steam app found for app ID 1.` Such an exception, and
`SteamConnectionException`, carries no previous one, so a `report()` callback finds no Saloon
exception in the chain — read Steam's status from `getCode()` and the payload from `response`.

A status no leaf claims — a `5xx` once the
[retries](/laravel-steam-api-sdk/configuration#timeouts-and-retries) are spent, an
unexpected `4xx` — arrives as `SteamApiException` itself, carrying the response and Steam's
status as the code.

The three marked as the bridge's own (`Fkrzski\LaravelSteamApiSdk\Exceptions`) signal a
misconfiguration, or a test wired up wrong, rather than a failed call — see
[Configuration](/laravel-steam-api-sdk/configuration). The rest live in
`Fkrzski\SteamApiSdk\Exceptions`. The base SDK's `InvalidTimeoutException`,
`InvalidRetryException` and `InvalidRateLimitException` never reach you: the bridge checks the
config before the base SDK sees it and raises `InvalidSteamConfigException` naming the key.

<Aside type="caution" title="Some failures fall outside the tree">
An empty ID list, a `concurrency` under 1 and a `newsFeed()` page under 2 raise
`InvalidArgumentException` before anything is sent. A DTO Steam's answer cannot fill fails the
call with whatever building it raised, such as PHP's `ValueError` for a friend `relationship` the
SDK does not list.
</Aside>

### Rendering

An exception that reaches Laravel's handler unhandled renders as the status it maps
to, rather than a blanket 500:

| Exception | Status |
| --- | --- |
| `SteamUserNotFoundException` | 404 |
| `AppNotFoundException` | 404 |
| `AppNewsUnavailableException` | 404 — Steam answers a 403, though the client asked for nothing forbidden |
| `AppVersionUnavailableException` | 404 — Steam answers an unknown app and one without server versions alike |
| `StatsUnavailableException` | 404 — the cause is ambiguous, so the status says nothing about which |
| `ProfileNotPublicException` | 403 |
| `InvalidServerAddressException` | 422 — the address is input, typically a route parameter |
| `SteamRateLimitException` | 429, with `Retry-After` counting down what is left of the limit's window, or of the cool-down after Steam's own `429` |
| `SteamConnectionException`, `UnreadableResponseException`, and `SteamApiException` for a `5xx` | 503, the body saying only `Service Unavailable` |
| `InvalidApiKeyException`, `TooManySteamIdsException`, `ApiKeyNotConfiguredException`, `InvalidSteamConfigException`, `FakeOutsideTestsException` | 500, the body saying only `Server Error` |

The 404, 403, 422 and 429 bodies carry the exception's message, which opens with the Steam
method when Steam answered.
With `app.debug` on, the 500 group is left to Laravel's exception page, still a 500, which names
what to fix.

`InvalidSteamIdException` and `FakeNotInstalledException` are left alone: an ID that
fails to parse is already a 404 from the [route binding](/laravel-steam-api-sdk/route-binding),
and a missing fake only happens in a test. Any other `SteamApiException` — an unexpected `4xx`, a
refusal Steam reports in a `200` — reaches Laravel's handler as it is, a plain 500.

Every row above the 500 one is turned off together by
[`steam-api.exceptions.render`](/laravel-steam-api-sdk/configuration#exception-rendering);
the 500 group is not, and never carries Steam's own status.
