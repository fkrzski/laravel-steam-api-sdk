title: Testing
description: Fake the Steam Web API with Steam::fake() — the base SDK's SteamFake on the scoped connector, retries without the pause, and assertions on the facade.
---

`Steam::fake()` attaches the base SDK's `SteamFake`, a Saloon
[`MockClient`](https://docs.saloon.dev/the-basics/testing), to the connector and returns it: no
request leaves your machine, and the assertions sit on the facade. The fake's endpoint methods,
the DTO factories and the failures it stages are documented in the base SDK's
[Testing](/php-steam-api-sdk/testing); this page covers what the bridge adds.

<Aside type="danger" title="Tests only">
`Steam::fake()` throws `FakeOutsideTestsException` unless the application environment is
`testing`. Nothing detaches the mock once it is attached.
</Aside>

## Faking responses

<Tabs syncKey="php-test-runner">
  <TabItem label="Pest">
    ```php title="tests/Feature/PlayerSummariesTest.php"
    use Fkrzski\LaravelSteamApiSdk\Facades\Steam;
    use Fkrzski\SteamApiSdk\Http\Requests\ISteamUser\GetPlayerSummariesRequest;
    use Fkrzski\SteamApiSdk\Testing\Factories\ISteamUser\PlayerSummaryFactory;
    use Fkrzski\SteamApiSdk\ValueObjects\SteamId;

    it('fetches player summaries', function (): void {
        Steam::fake()->users()->summaries(
            PlayerSummaryFactory::new()->personaName('Gabe')->online(),
        );

        $summaries = Steam::users()->summaries([SteamId::fromSteamId64('76561198000000000')]);

        expect($summaries[0]->personaName)->toBe('Gabe');

        Steam::assertSent(GetPlayerSummariesRequest::class);
    });
    ```
  </TabItem>
  <TabItem label="PHPUnit">
    ```php title="tests/Feature/PlayerSummariesTest.php"
    use Fkrzski\LaravelSteamApiSdk\Facades\Steam;
    use Fkrzski\SteamApiSdk\Http\Requests\ISteamUser\GetPlayerSummariesRequest;
    use Fkrzski\SteamApiSdk\Testing\Factories\ISteamUser\PlayerSummaryFactory;
    use Fkrzski\SteamApiSdk\ValueObjects\SteamId;

    final class PlayerSummariesTest extends TestCase
    {
        public function test_it_fetches_player_summaries(): void
        {
            Steam::fake()->users()->summaries(
                PlayerSummaryFactory::new()->personaName('Gabe')->online(),
            );

            $summaries = Steam::users()->summaries([SteamId::fromSteamId64('76561198000000000')]);

            $this->assertSame('Gabe', $summaries[0]->personaName);

            Steam::assertSent(GetPlayerSummariesRequest::class);
        }
    }
    ```
  </TabItem>
</Tabs>

Each endpoint method fakes the request its resource method sends and hands the fake back, so a
chain moves resource by resource: `Steam::fake()->users()->summaries(...)->stats()->currentPlayers(12_345)`.
The base SDK lists [every endpoint method](/php-steam-api-sdk/testing#faking-responses), the
[DTO factories](/php-steam-api-sdk/testing#dto-factories), each under
`Fkrzski\SteamApiSdk\Testing\Factories` and its Steam interface, and how a fake answers
[more than 100 Steam IDs](/php-steam-api-sdk/testing#more-than-100-steam-ids).

The fake sits on the [scoped](/laravel-steam-api-sdk/configuration#the-connector-binding)
connector, so it covers every call through the facade — resources, `newsFeed()`, `pool()` and
`send()` alike — and goes away with the request, job or test that installed it.
`->news()->newsFeed()` takes a whole feed, which
[`Steam::newsFeed()`](/laravel-steam-api-sdk/api-reference#newsfeed) walks the way it walks Steam.

`Steam::fake()` also takes a map of request class → `MockResponse`, for a request of your own sent
through `send()` or an answer the chain does not build, and the map combines with a chain:

```php
use Fkrzski\SteamApiSdk\Http\Requests\ISteamUser\GetPlayerBansRequest;
use Saloon\Http\Faking\MockResponse;

Steam::fake([
    GetPlayerBansRequest::class => MockResponse::make(['players' => []]),
])->users()->summaries();
```

A `MockResponse` needs the envelope the chain method would build, or the call raises
`UnreadableResponseException`.

## Faking failures

The refusals Steam answers an endpoint with sit beside it — `->users()->friendsNotPublic()`,
`->stats()->schemaAppNotFound()` and the rest, listed under
[Faking failures](/php-steam-api-sdk/testing#faking-failures) with the exception each raises:

<Tabs syncKey="php-test-runner">
  <TabItem label="Pest">
    ```php
    use Fkrzski\SteamApiSdk\Exceptions\ProfileNotPublicException;

    it('surfaces a private friend list', function (): void {
        Steam::fake()->users()->friendsNotPublic();

        Steam::users()->friends($steamId);
    })->throws(ProfileNotPublicException::class);
    ```
  </TabItem>
  <TabItem label="PHPUnit">
    ```php
    use Fkrzski\SteamApiSdk\Exceptions\ProfileNotPublicException;

    Steam::fake()->users()->friendsNotPublic();

    $this->expectException(ProfileNotPublicException::class);

    Steam::users()->friends($steamId);
    ```
  </TabItem>
</Tabs>

`->invalidApiKey()`, `->connectionFailed()` and `->tooManyRequests()` sit on the fake itself and
answer every request without a response of its own. `tooManyRequests()` raises
`SteamRateLimitException` the way Steam's own `429` does and starts the
[cool-down](/laravel-steam-api-sdk/rate-limiting#after-a-429): every later request sent the same
way, with the key or without it, is refused locally, before the fake can answer, for the
`retryAfter` seconds you pass, or `steam-api.rate_limit.cooldown` without them. The lock lives in
the rate limit store, so a second `Steam::fake()` in the same test does not lift it.

## Rate limits in tests

The budget and the lock after a faked `429` live in
[`steam-api.rate_limit.store`](/laravel-steam-api-sdk/rate-limiting#the-cache-store). Laravel's
`phpunit.xml` sets `CACHE_STORE` to `array`, which starts empty in every test, while a persistent
store such as `file` or `redis` carries both into the next test. Keep the rate limit store on
`array` even when `.env` names another:

```xml title="phpunit.xml" ins={3}
<php>
    <env name="CACHE_STORE" value="array"/>
    <env name="STEAM_API_RATE_LIMIT_STORE" value="array"/>
</php>
```

No fake stands in for a spent local limit, which is refused before a response exists. A limit of
one request does it in two calls:

```php
config(['steam-api.rate_limit.limits' => [['allow' => 1, 'every' => 60]]]);

Steam::fake()->stats()->currentPlayers(12_345);

Steam::stats()->currentPlayers(appId: 440);
Steam::stats()->currentPlayers(appId: 440); // SteamRateLimitException
```

## Retries

`Steam::fake()` keeps the tries the [config](/laravel-steam-api-sdk/configuration#timeouts-and-retries)
sets but drops the pause between them, whatever `interval` says, so a faked `5xx` is retried at
once and every attempt is counted. Set the tries first — `Steam::fake()` builds the connector:

```php
use Fkrzski\SteamApiSdk\Exceptions\SteamApiException;
use Fkrzski\SteamApiSdk\Http\Requests\ISteamUser\GetPlayerSummariesRequest;
use Saloon\Http\Faking\MockResponse;

config(['steam-api.http.retry.tries' => 3]);

Steam::fake([
    GetPlayerSummariesRequest::class => MockResponse::make(status: 503),
]);

try {
    Steam::users()->summaries([$steamId]);
} catch (SteamApiException) {
    // raised once the third attempt fails too
}

Steam::assertSentCount(3);
```

Saloon pauses with a bare `usleep()`, which `Sleep::fake()` cannot reach, so the fake skips the
wait rather than leaving a suite to sit it out. The pause a `sleep`
[rate limit](/laravel-steam-api-sdk/rate-limiting#waiting-instead-of-failing) takes is not
skipped, so a test sending more than such a limit allows waits the window out.

`connectionFailed()` is retried the same way, but it is recorded under neither `send()` nor
`pool()`: `recorded()` and the assertions never see the attempt, so assert on the exception.

## A key for the requests that need one

`Steam::fake()` swaps the HTTP client, not the connector, so a faked request that needs a key
still raises [`ApiKeyNotConfiguredException`](/laravel-steam-api-sdk/configuration#the-api-key)
when none is configured. No request leaves your machine, so the value is irrelevant:

```xml title="phpunit.xml" ins={4}
<phpunit>
    <php>
        <env name="APP_ENV" value="testing"/>
        <env name="STEAM_API_KEY" value="testing"/>
    </php>
</phpunit>
```

A suite covering only the `apps()`, `news()` and `webApi()` endpoints, `currentPlayers()`,
`globalAchievements()` and `newsFeed()` needs no key at all — Steam serves those anonymously, and
the connector sends them without one.

## Asserting

Saloon's assertions are proxied onto the facade, so nothing has to hold the mock:

```php
Steam::assertSent(GetPlayerSummariesRequest::class);
Steam::assertNotSent(GetPlayerBansRequest::class);
Steam::assertSentCount(1);
Steam::assertSentCount(1, GetPlayerSummariesRequest::class);
Steam::assertNothingSent();

Steam::assertSentInOrder([
    ResolveVanityUrlRequest::class,
    GetPlayerSummariesRequest::class,
]);
```

`assertSent()` and `assertNotSent()` also take a closure — assert on the request's query
parameters, body or headers when the class alone isn't enough:

```php
Steam::assertSent(
    fn (GetPlayerBansRequest $request): bool => $request->steamIds === $ids,
);
```

<Aside type="caution" title="Fake first">
Each assertion reads the mock `Steam::fake()` attached. Calling one without a fake raises
`FakeNotInstalledException` rather than passing on an empty history.
</Aside>

Saloon's `assertSentJson()` is deprecated upstream, so the facade does not proxy it — call it on
the mock if a test still needs it.

## Recorded traffic

When an assertion isn't the shape you want, the mock's readers sit on the facade too — the
recorded responses, and the last exchange:

<Tabs syncKey="php-test-runner">
  <TabItem label="Pest">
    ```php
    Steam::fake()->users()->summaries(PlayerSummaryFactory::new());

    Steam::users()->summaries([$steamId]);

    expect(Steam::recorded())->toHaveCount(1)
        ->and(Steam::lastRequest())->toBeInstanceOf(GetPlayerSummariesRequest::class)
        ->and(Steam::lastResponse()?->json('response.players'))->toHaveCount(1);
    ```
  </TabItem>
  <TabItem label="PHPUnit">
    ```php
    Steam::fake()->users()->summaries(PlayerSummaryFactory::new());

    Steam::users()->summaries([$steamId]);

    $this->assertCount(1, Steam::recorded());
    $this->assertInstanceOf(GetPlayerSummariesRequest::class, Steam::lastRequest());
    ```
  </TabItem>
</Tabs>

`recorded()` returns the Saloon `Response` objects in the order they came back. Both
`lastRequest()` and `lastResponse()` return `null` when nothing was sent — an empty history is not
a failure here, that is what `assertNothingSent()` is for. Without a fake they raise
`FakeNotInstalledException`, same as the assertions.

## Events

The [events](/laravel-steam-api-sdk/events) come from the connector, not from the HTTP client the
fake swaps, so a faked call dispatches them and `Event::fake()` records them, whichever of the two
is faked first:

```php
use Fkrzski\LaravelSteamApiSdk\Events\SteamResponseReceived;
use Illuminate\Support\Facades\Event;

Event::fake([SteamResponseReceived::class]);
Steam::fake()->users()->summaries(PlayerSummaryFactory::new());

Steam::users()->summaries([$steamId]);

Event::assertDispatched(
    SteamResponseReceived::class,
    fn (SteamResponseReceived $event): bool => $event->status === 200,
);
```
