The bridge wires the `SteamConnector` from a single config file. In most apps the
only value you set is your API key.

## Installing

<Tabs syncKey="steam-setup">
  <TabItem label="Installer">
    One command covers both setup steps:

    ```bash
    php artisan steam:install
    ```

    Publishes `config/steam-api.php`, then prompts for your
    [Steam Web API key](https://steamcommunity.com/dev) — hidden as you type — and
    appends `STEAM_API_KEY` to `.env`.

    Safe to re-run: an existing config file is kept, an existing key is replaced
    only once you confirm, and a blank answer leaves `.env` alone.
  </TabItem>
  <TabItem label="By hand">
    <Steps>

    1. Publish the config file:

       ```bash
       php artisan vendor:publish --tag=steam-api-config
       ```

    2. Add your [Steam Web API key](https://steamcommunity.com/dev) to `.env`:

       ```dotenv title=".env"
       STEAM_API_KEY=your-steam-web-api-key
       ```

    </Steps>
  </TabItem>
</Tabs>

## The config file

The provider merges its own `steam-api` config, so the package works unpublished.
Publish it when you want the file in your repo to override the defaults:

```bash
php artisan vendor:publish --tag=steam-api-config
```

This writes `config/steam-api.php`:

```php title="config/steam-api.php" "env('STEAM_API_KEY')"
return [

    // Your Steam Web API key, obtained from https://steamcommunity.com/dev.
    // Sent as the "key" query parameter on every request that needs one.
    'key' => env('STEAM_API_KEY'),

    // Steam's own language code, sent on every request whose payload is
    // localised. Unset, it follows the application locale.
    'language' => env('STEAM_API_LANGUAGE'),

    // How long to wait on Steam, in seconds, and how many attempts a request
    // Steam never answered, or answered with a 5xx, gets in all.
    'http' => [
        'connect_timeout' => env('STEAM_API_CONNECT_TIMEOUT'),
        'request_timeout' => env('STEAM_API_REQUEST_TIMEOUT'),

        'retry' => [
            'tries' => env('STEAM_API_RETRY_TRIES', 1),
            'interval' => env('STEAM_API_RETRY_INTERVAL', 0),
            'exponential_backoff' => env('STEAM_API_RETRY_EXPONENTIAL_BACKOFF', false),
        ],
    ],

    // The cache store holding the daily request counter. Unset, the default one.
    'rate_limit' => [
        'store' => env('STEAM_API_RATE_LIMIT_STORE'),
    ],

    // Resolve a route parameter into a SteamId value object. Opt-in. See the
    // route binding guide for details.
    'route_binding' => [
        'enabled' => false,
        'parameter' => 'steamId',
    ],

    // Render an unhandled Steam failure as the status it maps to instead of a
    // blanket 500. On by default.
    'exceptions' => [
        'render' => true,
    ],

    // The channel from config/logging.php failed Steam calls are logged to, and
    // whether every response is too. Unset, nothing is logged.
    'logging' => [
        'channel' => env('STEAM_API_LOG_CHANNEL'),
        'responses' => env('STEAM_API_LOG_RESPONSES', false),
    ],

];
```

## The API key

Set the key in `.env`. It is read through `config('steam-api.key')` and appended to
every request that needs one, so you never pass it per call:

```dotenv title=".env"
STEAM_API_KEY=your-steam-web-api-key
```

Get one from the [Steam Web API dashboard](https://steamcommunity.com/dev). The key is
optional: Steam serves `appNews()`, `currentPlayers()`, `globalAchievements()`, `newsFeed()`,
`sdrConfig()`, `serversAtAddress()` and `upToDateCheck()` anonymously, so those go out without
one. With
the key unset — or present but blank — any other request raises the base SDK's
`ApiKeyNotConfiguredException`. Its message says to pass a key to `SteamConfig`, which here
means setting `STEAM_API_KEY`, or `steam-api.key` directly.

<Aside title="The check runs per request, on purpose">
It fires as a request that needs a key is sent, before it goes out — not at boot, and not
when the connector is built — so an application boots, caches its config and publishes the
config file before a key exists.
</Aside>

<Aside type="caution" title="SteamApiKeyMissingException is gone since 0.7.0">
The base SDK refuses a keyless request before the bridge's own check could run, so catch
`ApiKeyNotConfiguredException` instead.
</Aside>

## Default language

Steam localises achievement names, descriptions and stat labels, and the connector carries
one language code on every request that reads them. The codes are Valve's own rather than
ISO ones — `koreana`, not `ko`; see `Fkrzski\SteamApiSdk\Enums\Language` for the list:

```dotenv title=".env"
STEAM_API_LANGUAGE=polish
```

| `steam-api.language` | What the request carries |
| --- | --- |
| unset — the default | the language the application locale maps to, or nothing where it maps to none |
| `''` | nothing; Steam picks |
| `'polish'` | `polish` |
| anything else | nothing goes out — `InvalidSteamLanguageException` instead |

A rejected code raises the first time the connector is resolved, so it surfaces on your
first Steam call rather than at boot. It is a misconfiguration, so it renders as a 500
whatever [`steam-api.exceptions.render`](#exception-rendering) says.

The `language:` argument on
[`achievements()`](/laravel-steam-api-sdk/api-reference#achievements),
[`schema()`](/laravel-steam-api-sdk/api-reference#schema) and
[`userStats()`](/laravel-steam-api-sdk/api-reference#userstats) overrides the default for
that one call.

### Following the locale

With `steam-api.language` unset, `Localization\LocaleLanguageResolver` maps `app()->getLocale()` through
a table of Valve's spellings: `pl` is `polish`, `ko` is `koreana`, `pt_BR` is `brazilian`.
A locale whose region Steam does not distinguish falls back to the base one — `de_AT` is
`german` — and one Steam publishes no language for sends nothing rather than raising.

Bind `Contracts\SteamLanguageResolver` when your application has a locale scheme of its own:

```php title="app/Providers/AppServiceProvider.php"
use Fkrzski\LaravelSteamApiSdk\Contracts\SteamLanguageResolver;

$this->app->bind(SteamLanguageResolver::class, TenantLanguageResolver::class);
```

<Aside type="caution" title="The locale is read once">
The connector is scoped, so it reads the locale when it is first built — a later
`App::setLocale()` does not reach it. Pass `language:` to the call to switch mid-request.
</Aside>

## Timeouts and retries

The `http` block sets how long the connector waits on Steam and how many times it tries,
each option from its own variable:

```dotenv title=".env"
STEAM_API_CONNECT_TIMEOUT=3
STEAM_API_REQUEST_TIMEOUT=60
STEAM_API_RETRY_TRIES=3
STEAM_API_RETRY_INTERVAL=500
STEAM_API_RETRY_EXPONENTIAL_BACKOFF=true
```

| Variable | Unset | Meaning |
| --- | --- | --- |
| `STEAM_API_CONNECT_TIMEOUT` | `10`, Saloon's | seconds to connect, `0` waits forever |
| `STEAM_API_REQUEST_TIMEOUT` | `30`, Saloon's | seconds for the whole request, `0` waits forever |
| `STEAM_API_RETRY_TRIES` | `1` | attempts in all, so `1` never retries |
| `STEAM_API_RETRY_INTERVAL` | `0` | milliseconds between attempts |
| `STEAM_API_RETRY_EXPONENTIAL_BACKOFF` | `false` | doubles the interval after each retry |

Only what can change by the next attempt is retried: Steam unreachable, a timeout, a `5xx`.
A `4xx` and a spent quota are thrown at once, and so is the `500`
[`sdrConfig()`](/laravel-steam-api-sdk/api-reference#sdrconfig) answers an unknown app with.
Once the tries are spent, a request Steam never answered raises `SteamConnectionException`
and a `5xx` the root `SteamApiException`. Requests sent through
[`pool()`](/laravel-steam-api-sdk/guide#concurrent-requests) go out once.

<Aside type="caution" title="Every attempt is a request">
Each retry spends one of the day's 100 000 requests, since the budget counts a `5xx` like
any other answer.
</Aside>

A value that is not a number, or is out of range, raises `InvalidSteamHttpOptionException`
naming the key. Like a rejected language code, it surfaces on your first Steam call and
renders as a 500.

## Route binding

The `route_binding` block resolves a route parameter straight into a `SteamId`. It
is **off by default** — the parameter name is claimed application-wide. Set
`enabled` to `true` to opt in; [Route binding](/laravel-steam-api-sdk/route-binding)
has the full guide.

## The connector binding

The provider binds `SteamConnector` as a **scoped** instance: one per request, torn
down with it. Under [Laravel Octane](https://laravel.com/docs/octane) and between
queue jobs the container outlives the request, and a shared connector would carry
its API key into the next one.

It resolves lazily, so a misconfigured option surfaces on your first Steam call rather
than at boot. Reach it through
[`Steam::connector()`](/laravel-steam-api-sdk/api-reference#connector) — for the
current request only.

## Contracts

`Contracts\SteamManager` is what the `Steam` facade resolves — type-hint it to inject the
manager instead of reaching through the facade:

```php title="app/Http/Controllers/PlayerController.php"
use Fkrzski\LaravelSteamApiSdk\Contracts\SteamManager;

final class PlayerController
{
    public function __construct(private readonly SteamManager $steam) {}
}
```

The contract and the concrete `SteamManager` resolve to one scoped instance, so binding
either swaps what the facade hands back — a decorator wrapping the shipped manager, say.
`Contracts\SteamIdBinder` is the same seam for the
[route binding](/laravel-steam-api-sdk/route-binding#swapping-the-resolver), and
`Contracts\SteamLanguageResolver` for the [locale mapping](#following-the-locale). Every
class the package ships is `final`; the container is the extension point.

## Rate limiting

The Steam Web API allows **100 000 requests per API key per day**. The connector
enforces this through [`saloonphp/rate-limit-plugin`](https://github.com/saloonphp/rate-limit-plugin)
and throws `SteamRateLimitException` once the budget is spent. With no key configured it
counts nothing, since Steam bills the quota to the key, and a `429` from Steam still raises
`SteamRateLimitException`.

The counter is keyed by the API key itself — hashed, so the key never lands in the
store — rather than by the connector class. Two keys in one application draw down two
budgets.

The counter lives in a Laravel cache store, not per-process memory, so with a shared driver
(Redis, database, Memcached) every FPM worker, queue worker and Octane process draws down one
budget. It is the default store until you name another:

```dotenv title=".env"
STEAM_API_RATE_LIMIT_STORE=redis
```

Give it a store of its own: `cache:clear` flushes the default one, resetting the count while
Steam's own carries on. A store that evicts keys under memory pressure — Redis with an
eviction policy, Memcached — can drop the counter too. A name `cache.stores` does not define
raises `InvalidSteamRateLimitStoreException` on your first Steam call, rendered as a 500.

<Aside type="caution" title="The array and file drivers do not share">
Those two keep the budget per process — fine locally, but pick a shared driver in
production so the quota is enforced app-wide.
</Aside>

<Aside title="The upgrade to 0.4.0 orphans the old counter">
It was keyed by the connector class, so a persistent store reads no count under the
new key and reports the full 100 000 once. What Steam itself has already counted is
untouched.
</Aside>

## Queued jobs

Left alone, a job that hits the spent budget fails like on any other exception.
`Queue\Middleware\RespectsSteamRateLimit` releases it for what is left of the window instead
— before it runs once the budget is spent, or when a request inside it raises
`SteamRateLimitException`:

```php title="app/Jobs/SyncPlayerStats.php"
use Fkrzski\LaravelSteamApiSdk\Queue\Middleware\RespectsSteamRateLimit;

public function middleware(): array
{
    return [new RespectsSteamRateLimit];
}

public function retryUntil(): DateTime
{
    return now()->addDay();
}
```

A release counts as an attempt, so a job waiting out a daily window wants `retryUntil()`
rather than a small `$tries`. The middleware releases through `InteractsWithQueue`, and lets
a job without it run unguarded. With no key configured nothing is metered, so only a `429`
from Steam holds a job back.

## Exception rendering

A Steam failure nothing in the application caught renders as the status it maps to
rather than a blanket 500 — [the guide](/laravel-steam-api-sdk/guide#rendering) has the
table. Turn the group off to render it yourself:

```php title="config/steam-api.php" "false"
'exceptions' => [
    'render' => false,
],
```

The flag does not reach misconfiguration. A rejected API key, a missing one, a batch over
100 IDs, and a language code, HTTP option, rate limit store or logging option the config cannot
use are a 500 whatever it is set to: Steam answers a bad key with a 400 or a 403, and passing that on
would blame the caller for something only you can fix.

<Aside title="Your own renderer wins either way">
Callbacks registered in `bootstrap/app.php` run ahead of the package's, so a
`renderable()` of your own takes the exception first. Reach for the flag only to turn
the whole group off.
</Aside>

## Logging

The `logging` block logs Steam traffic to a channel of yours. It is **off by default** — set
`STEAM_API_LOG_CHANNEL` to opt in, and `STEAM_API_LOG_RESPONSES` to log every response too;
[Logging](/laravel-steam-api-sdk/logging) has the full guide.

## Checking your setup

The provider registers a **Steam API** section on Laravel's `about` command:

```bash
php artisan about --only=steam_api
```

```text frame="terminal" title="php artisan about --only=steam_api"
  Steam API .............................................................
  API Key .................................................. ********4f2a
  Daily Requests Remaining ............................ 99,412 of 100,000
  Language .......................................... polish (locale: pl)
  Logging ........................................... steam (+ responses)
  Rate Limit Store ................................................ redis
  Retries ............................. 3 attempts, 500ms apart, doubling
  Route Binding ....................................... enabled (steamId)
  Timeouts ...................................... connect 3s, request 60s
```

- **API Key** — masked to its last four characters, so the output is safe to paste
  into a bug report. `NOT SET` when no key is configured.
- **Rate Limit Store** — the cache store the counter lives in, marked `(default)` while
  `steam-api.rate_limit.store` is unset.
- **Daily Requests Remaining** — what is left of the 100 000, read from that store.
  `not metered (no API key)` with no key configured, since Steam bills the budget to the key,
  and `UNKNOWN` while another row reads `INVALID`, since the connector cannot be built.
- **Language** — the code every localised request carries, and which of the two answers it
  is: `polish (config)` or `polish (locale: pl)`. `NOT SET` names its source the same way,
  and `INVALID` stands alone, since only config can carry a rejected code.
- **Logging** — `disabled` until a channel is set, then its name, with `(+ responses)` once
  every response is logged too.
- **Route Binding** — `disabled`, or `enabled` with the parameter name it claims.
- **Timeouts** — the connect and request timeouts, Saloon's own marked `(default)`, and
  `unlimited` for `0`.
- **Retries** — `none (default)` for a single attempt, otherwise the attempts and the pause
  between them.

The store, timeout, retry and logging rows read `INVALID` for a value the connector does not
take.

Nothing here runs on boot: the values are computed when the command renders, and no
request is sent to Steam.
